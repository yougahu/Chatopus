# 本地审计后台

```sh
npm run admin
```

默认地址 `http://127.0.0.1:8092`，可通过 `npm run admin -- --port 8093` 更换端口。后台独立于群机器人运行，即使机器人停止也能检查历史状态。审计页面只读取数据库与模型会话；配置页面可以修改业务提示词、能力选择、人格正文、唤起关键字、Router、Worker 和记忆提炼模型。定时任务页面保存计划和管理请求，由机器人服务执行并投递群消息；后台本身不启动调度器。保存并应用记忆模型可能重启受支持的外部后端。

后台无需登录，仅供可信本机用户使用；需要远程访问时，由部署者另外配置身份认证和网络隔离。

后台包含：

- 运行概览：消息数、执行中/等待的 Thread、Router 耗时、模型 token 用量、失败或未知投递、最近异常。
- 任务话题：筛选群和状态，从原始问题、补充条件追踪到执行、答案和发送结果。
- 定时任务：管理单次与循环计划、配置群聊登记权限，查看最近执行、连续失败、模型用量、独立的投递状态和操作审计。
- 群消息与路由决策：查看哪些消息被静默、短答、交给 Worker 或归入已有话题。
- 回复投递：区分 pending、sent、failed、unknown 和 stale。unknown 不等于确定失败，不自动盲目重发。
- 模型与工具轨迹：读取真实 dsh JSONL 中的工具调用、结果与最终答复，省略思考流及大段内部系统提示。
- 记忆：按群选择本地已知成员，查看 OpenViking 当前明确画像及字段来源，搜索历史语义记忆、分页读取原文，检查本地持久化摄取进度。已清除和已过期字段保留可辨识状态。
- 模型 · 插件：Router 和 Worker 各自编辑模型、API 地址、协议、推理等级和 API Key。密钥仅显示是否已配置；留空表示保留原密钥，保存后密码框清空。可查看额外插件模块，插件 options 不展示。
- 业务 · 提示词：创建业务、编辑指引、选择已注册技能/扩展/成员字段、配置业务人格及群绑定，预览、保存和回退。

“模型 · 插件”页顶部可编辑“唤起关键字”，对应全局 `botCallNames`。支持换行或中英文逗号分隔，保存时去除首尾空白并按英文大小写不敏感去重；最多32个，每个最多80个字符。清空并保存表示仅通过 @ 唤起。关键词仍只是候选，Router 会判断是否在直接呼唤机器人。页面显示已保存的值，**修改后需重启机器人生效**；保存不会自动重启或中断现有任务。

数据源可切换“当前服务”和最近终端 `ask` 验证。各源的消息、Thread、投递和模型轨迹保持对应；不存在主数据库时显示空状态，不伪装机器人在线。数据表每页最多 100 行，模型轨迹显示最近 300 个可展示事件。

回复投递列表区分图片和群文件，并显示已上传文件数。投递详情、话题的回复记录、定时任务执行详情均显示文件名、大小、逐文件上传状态、尝试次数和失败原因。每个文件独立确认；整体回复失败或未知时，已上传的文件仍显示为成功。文件全部确认后才发送正文，重试不会重复上传已确认的文件；上传结果未知时停止后续投递。取消后的未上传文件显示“未上传”，已有文件不会撤回。页面及附件审计不展示文件的本地路径，也不提供文件下载功能。

任务列表和详情分别展示每个 Thread 的输入与输出 token，详情可展开查看各次执行。统计使用当前数据源中该任务的全部 `model`/`worker` 用量记录，不受概览最近 300 条记录或任务列表分页限制。同一任务的多次执行与格式修复累加；记录中的上下文摘要已包含在总量内，不重复相加。适配器将未缓存输入、缓存读取和缓存写入分别报告，因此输入总量是三者之和，详情保留缓存分项。

这里是已记录的 Worker 用量，不是完整费用账单：共享 Router 与独立记忆调用不分摊到任务，未返回或未落盘的用量无法补算。当前执行在本轮结束后更新；历史记录可直接汇总，没有记录时显示“未记录”，存在尚无用量记录的执行时提示累计可能不完整。

记忆页仅对“当前服务”开放。历史 `ask` 数据源显示不可用，不回退到生产 OpenViking。群和成员来自当前数据库，后端使用与机器人相同的 namespace、机器人身份、群作用域计算 account。浏览器不能指定 account、API Key 或磁盘路径。后台只查询已有 USER 凭据，打开页面不会自动创建账号、用户、画像或触发摄取。

成员列表与画像在桌面并排显示，各自独立滚动。成员列表到底自动继续加载，每次最多 50 人；可按 QQ 号或群昵称搜索当前群的全部已记录成员，昵称取最近消息里的群名片（没有群名片则使用 QQ 昵称）。手机端选择成员后在原位置切换到画像，使用“返回成员”保留原列表位置。摄取进度默认折叠在下方。

“已配置”只表示配置可用；查看画像、检索和读取原文会单独显示实际结果或失败。成员数量来自已接收消息，不代表已生成画像数量。摄取游标和批次状态来自本地数据库，不作为远端记忆条数或向量索引已就绪的证明。字段来源只打开同群原始消息，历史回复来源只接受已确认发送的 Outbox 记录。

只读记忆 API：

| GET 路径 | 参数 | 用途 |
| --- | --- | --- |
| `/api/memory` | `source` | 功能状态与已知群 |
| `/api/memory/members` | `room`、`offset`、`limit`、可选 `q` | 按 QQ 号或最新群昵称包含匹配，分页列出同群已知成员 |
| `/api/memory/profile` | `room`、`member` | 当前明确画像、字段状态及来源 |
| `/api/memory/search` | `room`、`q`、可选 `member` | 群内或指定成员的历史语义检索 |
| `/api/memory/content` | `room`、`uri`、可选 `offset` | 有界分页读取允许的记忆原文 |
| `/api/memory/source` | `room`、`id` | 同群原始消息或已确认发送的回复 |
| `/api/memory/status` | `room` | 当前账号对应的本地摄取进度 |

这些接口不提供编辑、删除、重建索引或重试写入操作；OpenViking 凭据只在服务端使用。启用配置变更与既有插件设置一样，需要重启后台生效。

模型配置保存在私有 `config.local.json`，密钥分别写入 `.env` 的 `ROUTER_API_KEY` 与 `WORKER_API_KEY`，权限为600。两个角色可使用不同账户、不同地址和不同模型。新的模型调用自动读取更新；正在执行的 Worker 继续使用启动时的配置，完成后回收旧运行实例。通用插件和平台配置变更仍需重启。

服务只监听 loopback，校验 Host/Origin，页面和 API 均可直接访问。审计只允许 GET；配置写入口使用同源 JSON POST：`/api/model-config` 只接受两种角色的模型字段，`/api/activation-config` 只接受 `botCallNames` 数组，`/api/openviking-model-config` 及其 `/apply` 子路径负责记忆模型保存与应用。业务保存、回退和预览使用 `/api/business-config` 及其子路径，见 [业务 API](business-config.md)。所有聊天内容按文本渲染，避免消息中的 HTML 在后台执行。密钥和图片 base64 会在展示前过滤；访问后台意味着可以查看群消息内容并修改配置，因此不要直接暴露到公网。

验证：`tests/admin.test.ts` 覆盖访问、只读、跨来源限制、凭据隐藏、链路关联和静态资源；`scripts/admin-smoke.mjs` 在实际 Chrome 中检查桌面/手机布局、切换数据源、Thread 追踪、工具轨迹与配置隐藏。该脚本需要已有任务和至少一条工具轨迹，并断言概览没有已记录异常，不适合直接验收空安装或带历史异常的生产库。应使用准备好的合成审计数据。

浏览器探针依赖本机另行安装的 Playwright 和 Chrome，主项目没有将其列为默认测试依赖。`ADMIN_SMOKE_BASE_URL` 指定后台地址，`ADMIN_SMOKE_PLAYWRIGHT_MODULE` 可指定 Playwright 模块，`ADMIN_SMOKE_CHROMIUM_EXECUTABLE` 可指定浏览器路径，`ADMIN_SMOKE_OUTPUT_DIR` 指定输出目录；未覆盖时截图与报告位于 `.runtime/verification/admin/`。空安装的后台访问、空状态及 API 验证由离线后台测试覆盖。

## 定时任务管理

任务可选填多个收件人成员 ID（`recipientIds`，最多 50 个），QQ 群使用 QQ 号；固定提醒和 Worker 群结果投递时逐个 @。表单支持逗号、空格或换行分隔并去重，详情展示已保存的名单。留空或传入 `[]` 只发群消息；API 更新省略此字段时保留原名单。仅保存后台的任务不发送消息。收件人须显式设置，不从正文推断。

“定时任务”仅对“当前服务”提供管理。历史 `ask` 数据源不提供任务读写入口，不会回退到当前服务执行操作。要执行已保存的计划，需在部署配置启用 `scheduledTasks.enabled` 并配置允许群；未启用或机器人离线时仍可保存计划，页面如实显示执行条件。只有持有状态目录锁的机器人服务负责扫描、执行和投递。

后台新建任务始终为**系统任务**，群主、管理员和成员均不能在群聊中修改。后台编辑用户任务保留其用户级别、请求人和登记来源。任务归属由请求人决定，与 Router 或 Worker 登记无关；成员可以向 Router 查询自己的任务。获准的成员仅管理自己的任务；获准的群主／管理员可以管理本群用户任务。

“群聊任务权限”有“群主／管理员”和“成员”两个选项，支持多选、全选和全不选，默认两项均选中。空选关闭群聊中的新登记与管理，已有计划继续执行，请求人仍可查询自己的任务。权限保存到当前状态库，版本检查通过后立即生效，无需重启；平台角色依据来自 OneBot，角色不明、过期或核验失败时不授予管理权限。

创建表单可选择目标群、Worker 处理或固定文字提醒、时区、单次时间、固定间隔或五字段 cron，并预览未来执行时间。单次任务没有周期频率限制；周期任务默认最多每小时执行一次，部署可以进一步降低频率。周期的自动触发、补跑和“立即执行”共用限制。cron 分钟字段必须为单一数字；例如 `0 9 * * 1-5` 表示所选时区工作日 09:00。

表单同时支持补跑策略与有效窗口、执行硬超时、最多触发次数、结束时间和所需能力 ID。后台创建使用当时已保存的群业务配置。Worker 任务执行前会检查群、业务绑定和所需能力；配置变化导致条件不满足时显示阻塞原因。调整条件后可恢复；若有意切换业务，应重新确认任务说明并创建适用于新业务的任务。

列表支持按群、请求人、系统／用户级别、状态和标题筛选。详情支持编辑、暂停、恢复、取消、立即执行、停止单次执行和归档。暂停停止后续和未开始执行；取消还使当前执行失效并请求中止；“只停止本次执行”保留后续循环。已开始发送的消息无法撤回。保存使用版本与幂等标识，冲突时保留草稿；立即执行请求有有效期，后台显示排队结果，可查询处理状态，过期请求不会在服务恢复后无限补执行。

每次 Worker 执行使用独立话题，成功结果带任务标题投递到绑定群；固定文字提醒直接进入相同 Outbox 投递通道。详情分别展示执行状态和投递状态，计算完成不等于群消息已送达；`unknown` 表示无法确认送达，不盲目重发。可继续查看对应话题、模型轨迹、Token 用量、授权来源与最近审计。

任务 API 使用同源 JSON POST 写入，读取使用 GET：

| 路径 | 方法与用途 |
| --- | --- |
| `/api/schedules` | GET 列表／筛选／分页；POST 创建系统任务 |
| `/api/schedules/preview` | POST 按时区预览未来执行时间 |
| `/api/schedules/:id` | GET 计划、服务状态与最近审计 |
| `/api/schedules/:id/runs` | GET 执行历史、用量与实际 Outbox 投递记录 |
| `/api/schedules/:id/update` | POST 编辑，携带 `expectedVersion`、`patch`、`idempotencyKey` |
| `/api/schedules/:id/commands` | POST `pause`、`resume`、`cancel`、`run_now`、`stop_run`、`archive`；携带版本及幂等标识，停止单次执行需 `runId` |
| `/api/schedule-commands/:id` | GET 操作状态、回执或拒绝原因 |
| `/api/schedule-permissions` | GET 全局角色策略；POST `allowedRoleGroups` 与 `expectedVersion` |

创建请求为 `{ "input": { ... }, "idempotencyKey": "..." }`；表单中的本地时间由服务端按指定 IANA 时区解析。策略值仅接受 `group_admin` 和 `member`。请求人、权限级别和登记来源不能由浏览器在创建输入中指定。部署字段及默认值见 [配置参考](configuration.md#定时任务)。

`tests/admin-schedules.test.ts` 覆盖真实 HTTP 接口、归属与权限、离线状态、历史源隔离、时区、业务热切换、命令和投递审计；`tests/admin-schedules-ui.test.ts` 覆盖表单、草稿保留、请求中保护、确认操作与执行／投递区分。测试使用临时数据库与中性数据。

`tests/admin-files-ui.test.ts` 覆盖普通及定时回复的文件展示、部分上传状态、取消后的剩余文件、文件名转义、附件路径隐藏及已有图片回复兼容。

## 业务与提示词配置

“业务 · 提示词”页独立管理共同业务背景、Router／Worker 指引、已注册技能和扩展引用、人格正文、自定义成员字段选择与按群绑定。支持新增配置、预览未保存提示词、保存全部配置、查看版本及回退。保存采用版本检查，冲突时保留表单草稿并提示刷新。不会在此页面安装插件或调用模型。技能 ZIP 上传、目录同步和字段定义编辑尚未提供；安装步骤见 [技能和扩展](skills.md)，字段注册见 [自定义成员字段](member-fields.md)。

人格仅在“业务 · 提示词 → 记忆与风格 → 业务专属人格”中配置。直接填写 Markdown 正文，最多 8,000 个 Unicode 字符，随“保存全部配置”保存。Router 和 Worker 读取当前业务的人格，留空时不加载额外人格；不存在群专属或全局人格继承。旧文件内容自动带入编辑框，保存后迁移为正文，不修改原文件；读取失败时须填写替代内容或明确清空。

新调用使用最新业务配置，在途任务保持原快照；修改唤起关键字仍按既有规则重启后生效。预览明确区分固定提示词内容与运行时注入的工具、成员字段及任务上下文。具体结构和 API 见 [业务配置](business-config.md)。
