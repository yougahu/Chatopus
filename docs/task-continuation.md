# 任务追问与交付

引用消息帮助 Chatopus 找到讨论中的任务，Router 再根据当前消息区分查询和新要求。

| 请求 | 行为 |
| --- | --- |
| “现在进度如何？” | 返回任务状态，不重新执行 |
| “把交给 Worker 的内容给我看” | 返回已保存的交接解释，不新增任务输入 |
| “预算改为 300 元” | 保存更正，结束旧运行，再恢复同一任务会话 |
| “预算改为 300 元，并把交接内容给我看” | 一次保存更正并发送交接回执，后续交付研究结果 |
| “停止这个任务” | 按原提问者或管理员权限取消，不自动继续 |

交接解释是 Router 当时保存的任务理解，不是完整系统提示词，也不代表 Worker 已经读完所有材料。查询可选择当前记录、上一条记录或相邻两条记录；缺少历史解释时会明确说明。回执描述查询或更正提交时的事实，后续更正不会使它被静默撤销。

## 继续同一任务

更正先持久化，宿主再取消旧运行。旧实例完成会话保存、工具结算和资源清理后，重新创建执行实例，恢复相同逻辑会话，并通过正常追问入口提交新输入。历史消息、已完成工具结果及原文索引保留。运行 ID、版本和工具绑定会更新。

连续追加通过可配置的短窗口合并启动，所有原文、作者和顺序仍各自保存。默认最后一条输入后等待 750 毫秒，最多等待 3 秒。查询不会重置执行预算；同一版本的重试共享时间和步骤额度。

旧版本报告不能作为新版本答案发送。已明确唤起、且引用能关联到任务的待路由消息，还会暂缓该任务的新运行及最终投递。若这条消息路由失败，后台显示 `related_input_unresolved`，需要先核对失败消息并明确继续处理；不会自动放行旧答案。尚未通过语义判断归属的无引用消息不阻塞全群任务。

## 取消和投递的边界

取消不能撤销已发生的外部写入。不配合取消的工具仍占用旧实例，宿主等待它结算，不并行启动同任务的新实例；超过 5 秒记录“等待旧运行退出”。恢复时结果未知的外部操作应先核对，不能仅凭取消就认定未执行。

OneBot 确认成功的发送不会重复执行。超时、断连、缺少有效消息 ID 或不能证明未执行的处理器错误标为“发送结果待确认”，停止自动重发。当前适配器将请求校验拒绝 `1400`、未知 API `1404` 视为明确失败且不自动重试。平台已经受理的消息无法由版本校验撤回。

后台任务详情展示保存的交接解释、输入绑定版本、旧运行退出、合批等待及逐次投递回执。`superseded` 表示正常被新输入替代，不是任务故障；已消耗的模型 token 仍计入用量，缺失用量保持未知。

## 更新与回退

上线前停止领取新任务，等待或受控结束旧运行，备份数据库、会话目录和配置，再替换服务。检查未发送和结果未知的 Outbox，不自动补发未知消息。

本版本增加 `request_handoff` 与 `immediateReply` 协议。回退到不认识这些字段的版本前，应结清或隔离相关待处理 Router turn 和 Outbox，并保留期间新增的输入及已发送记录。不要用旧数据库覆盖新收到的消息。
