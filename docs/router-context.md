# Router 上下文与恢复

公开示例启用 `persistentRouter: true`。每个群使用持续的 dsh 会话；SQLite 保存消息原文、任务状态和提交记录。模型会话在需要时压缩，无法继续使用时从持久状态重建。

## 输入与召回

本轮输入包括当前消息、必要引用、任务卡片和已核实的结果。成员资料、原始消息、任务条件和发送回执按各自的来源读取，摘要不能代替这些记录或扩大操作权限。

输入序列化上限为 64 KB。当前原文及必要引用超限时明确失败并保留原文；普通历史可以有界省略，同时保留缺失标记及检索入口。模型工作区软目标约 48k token、硬限最多 64k，并有 256 KB 字节保护；实际值受模型容量和输出预留约束，token 计数是估算。

Router 可以检索同群历史，最多四次召回、每次最多四个对象。长正文分页读取并记录覆盖情况；未完成读取的材料不能支持执行型答案，可以用于澄清。较长任务条件通过 `task_inputs` 分页提供给 Worker。

## 压缩与重建

dsh 的压缩和工具结果裁剪器维护会话历史，宿主通过摘要 hook 提供群聊摘要规则。摘要截断后采用更短的策略；持续失败、上下文溢出、会话损坏或未完成的原生调用会触发状态重建。

重建隔离原物理会话，从 SQLite 创建新会话，不依赖模型先生成摘要。一个 turn 最多重建一次，动作仍由原 turn 的事务提交。输出校验失败可以在同一会话内进行有界纠正，已读取上下文保留，权限和预算校验继续生效。

物理日志轮换只在安全边界复制已生效历史和框架状态；验证并落盘后再切换指针，不额外调用模型。`routerSessionMaxBytes` 是换代阈值，不是总磁盘配额。

## 时限与预算

| 边界 | 默认值 |
| --- | --- |
| 同一 turn 总时限 | 120 秒 |
| 从消息入库起的总时限 | 180 秒 |
| 底层模型请求 | 最多 12 次，包含重试 |
| 摘要请求 | 最多 2 次，计入模型请求 |
| 状态重建 | 最多 1 次 |

时限和计数持久化，重启不会重置。总时限包含读取、推理、压缩、纠正和恢复；参数见 [配置参考](configuration.md)。

截止后宿主停止等待并释放同群队列，迟到结果不能提交。底层资源的最终清理仍依赖适配器响应取消或进程退出。外部操作结果不确定时，只核对原意图，不在恢复中换成新操作。

供应商耗尽重试或总时限后进入 30 秒熔断，同一提供方跨群共享；并发请求仅允许一个恢复探测，新请求和重启不清除熔断。

## 检查与维护

后台可查看 Router 处理状态、积压和模型调用。恢复后核对原始输入、终态、任务与 Outbox，而不只查看进程是否在线。状态备份和已有部署升级见 [运行维护](operations.md)。

离线测试覆盖恢复、压缩、作用域、预算、分页、事务和日志轮换。真实提供方压缩探针及普通语义回放的范围不同，见 [验证方法](verification.md)。
