# 人格配置

人格只影响称呼、语气和表达风格。业务范围及角色指引位于业务配置；身份权限、任务归属、结构化协议和投递规则由宿主约束。

后台入口是“业务 · 提示词 → 记忆与风格 → 业务专属人格”。直接在正文框填写内容，支持 Markdown，最多 8,000 个 Unicode 字符；点击“保存全部配置”后生效，保存在 `business.profiles.<id>.personaText`。Router 和 Worker 共用当前业务的人格，使用同一业务的群采用相同人格。

内容可选，留空或点击“清空人格”后保存，不再加载额外人格。没有群专属人格、全局默认人格或继承机制。仓库提供 `personas/default.md`、`personas/concise.md` 和 `personas/friendly.md` 三个中性模板，可以复制正文后自行调整；新部署和新增空白业务均不自动选择人格。

正文与业务配置一起保存、预览和回退。新调用读取最新内容，已开始的调用保持原配置。人格通过 Cordis 插件贡献独立提示词段落；群聊内容不能直接修改运营者的人格配置。

旧的业务 `personaFile` 仍可读取。打开后台时，可用文件的正文会自动带入编辑框；保存后改为正文配置，不改写原文件。读取失败时显示错误并保留原引用，其他字段的修改不会将其默认为空；需要直接填写替代正文，或明确点击“清空人格”后保存。若文件在载入后发生变化，未经编辑的旧正文会触发冲突提示，避免覆盖更新。

显式 `personaText` 优先于 `personaFile`，包括空字符串；只有未设置正文时才读取旧文件。旧文件支持相对项目目录的路径、绝对路径和 `~/`，必须可读、非空且不超过 8,000 字符。含旧文件引用的历史版本回退时仍会校验文件，新保存的正文版本无需原文件。顶层 `personaFile` 和 `roomPersonaFiles` 已不再读取；如不同群需要不同风格，创建独立业务并通过群绑定选择。
