# 定时任务

定时任务支持固定文字提醒和需要 Worker 执行的计划。默认关闭；在 `scheduledTasks.enabled` 中启用，并配置 QQ 身份和允许群。只有持有状态目录锁的机器人服务执行扫描，管理后台负责保存计划与操作请求。

## 创建计划

| 入口 | 任务类型 | 管理范围 |
| --- | --- | --- |
| 群聊 Router 或 Worker | 用户任务 | 当前群、当前请求人，受角色策略约束 |
| 本地管理后台 | 系统任务 | 后台可管理用户和系统任务 |

计划绑定一个允许群。固定提醒到期后直接写入 Outbox；Worker 任务创建独立 Thread，按该群启用的业务与能力执行。示例：“明天下午三点提醒我检查文档”或“每周一上午九点整理已配置资料”。复杂任务需明确内容和交付范围，不能登记任意系统命令。

`reminder` 不调用模型，`content` 必须是最终发送的固定文字；需要每次创作、翻译、总结或处理内容的计划应使用 `worker`，`content` 保存完整工作要求，即使不需要检索或工具也一样。模型修改 `content` 时必须先读取旧任务，并同时提交明确的 `executionKind`；仅修改时间或收件人不受此限制。提交回执显示执行方式，便于当场核对。

计划包含标题、内容、时间规则、时区和投递方式，可选设置有效期、最大执行次数、所需能力及收件人。QQ 收件人使用明确的成员 ID，最多 50 个，投递时生成真实 @；仅填写昵称不能替代身份确认。用户明确要求向自己交付时，可使用来源消息的作者 ID；内容中的人物或主题不是收件人，群广播不默认 @ 创建者。

## 时间规则

| 规则 | 行为 |
| --- | --- |
| 单次 | 明确日期时间或相对延迟，不受周期频率限制 |
| 固定间隔 | 从锚点计算，间隔至少一小时 |
| 日历循环 | 每天、每周、工作日或受限五字段 cron |

周期任务相邻两次实际开始时间至少相隔一小时。系统任务、自动触发、补跑和立即执行共用该限制；编辑计划不会重置计时。每个计划同一时间只执行一个实例。

时区使用 IANA 名称，默认 `Asia/Shanghai`。cron 的分钟字段必须为单个数字，日与星期字段不能同时限制。夏令时不存在的时刻跳过，重复时刻只取第一次；月份中不存在的日期跳过。后台预览未来五次时间。

服务错过触发时刻时，可按 `misfirePolicy` 合并补跑一次或跳过；默认补跑窗口为一天。不会为每个错过的周期堆积执行。完整限额见 [配置参考](configuration.md#定时任务)。

## 权限

后台“群主／管理员”和“成员”两个角色选项控制群聊登记及管理权限，支持多选或全部关闭。群主与管理员属于同一组；角色未知、过期或无法核验时拒绝写入。策略只决定操作权限，不把用户任务变成系统任务。

用户可以查询自己的已有任务；同群授权管理员可以管理该群的用户任务。系统任务只允许后台管理，群聊引用、追加、取消话题及构造工具参数均不能绕过这一边界。

Worker 提出的变更先保存为提案，最终提交时重新核对请求人、角色、来源、任务版本和执行有效性。多作者话题中，仅请求人本人最新有效且明确唤起的输入提供计划授权。其他成员的补充不能借用其身份登记计划。

## 执行和状态

计划状态包括 `active`、`paused`、`blocked`、`completed`、`cancelled`；执行实例另行记录排队、运行、成功、失败、取消、跳过或需补充信息。

后台支持修改、暂停、恢复、立即执行、停止本次执行、取消和归档。暂停保留计划；停止本次执行保留未来循环；取消使后续触发和未发送结果失效。归档仅改变展示，仍保留审计。

计划版本用于并发修改校验，执行 generation 用于取消和结果失效。重复来源按幂等键返回已有回执。服务重启恢复持久实例，不为同一次触发创建第二份任务；能力缺失或执行配置变化会阻塞，不静默换用其他业务。

Worker 执行与消息投递独立记录。结果入库不代表群已收到，Outbox 状态须另行核对。不确定投递不会自动重发；已上传文件不会因后续取消而自动撤回。

## 本地系统任务

后台可为系统 Worker 任务设置 `deliveryMode: "local"`，将结果和错误保存在本地，保留模型轨迹及产物，不创建群消息 Outbox。完成后投递状态为 `stored`，不再阻塞后续周期；省略该字段时投递到群。用户任务和固定提醒不接受本地投递。

扩展可读取宿主提供的 `context.execution`（执行类型、权限级别、计划及实例 ID），并按显式部署策略提供维护工具。聊天文本不能授予系统任务身份，领域写入、锁定和恢复仍由外部扩展负责。

## 维护

关闭定时功能并重启后，未结束计划暂停，在途执行及未发送结果失效。重新启用不自动恢复计划，应先核对原因并手动恢复。调整群角色策略只影响后续操作，不自动取消此前已获准的计划。

升级和备份应同时停止机器人与后台写入，保存完整状态。恢复后检查计划、实例、待提交命令、投递和数据库完整性。后台操作和 API 见 [任务管理](admin.md#定时任务管理)，代码接口位于 [types.ts](../src/scheduled-tasks/types.ts)。

## 私聊个人计划

完整 `qq:<bot>:private:<peer>` 会话内，只有本人可管理自己的用户计划，不继承群管理员权限。系统计划只由后台管理。全局开关仍有效。Worker 计划支持明确选择 `attachmentIds`，实例冻结文件版本及 `deliveryExpiresAt`。缺条件时暂停并创建独立普通跟进任务；未知投递逐项结案后仍需明确恢复，循环只排未来时刻。详细规则与示例见 [私聊使用说明](private-chat.md)。
