# 架构

Chatopus 是自托管的群聊 Agent 宿主，架构灵感来自 DeepSeek Super-agent。Router 负责参与判断和任务协调，独立 Worker 负责处理资料、调用工具和生成结果。二者都运行在原生 dsh Agent 上。

```text
OneBot → 消息入库 → Router → Thread → Worker → 结果校验
                      ↑                         ↓
                      └────── Outbox ←──────────┘
                                ↓
                           OneBot 回执
```

## 职责

| 组件 | 职责 |
| --- | --- |
| 平台适配器 | 认证、消息规范化、附件解析及投递回执 |
| Router | 判断是否参与，直接回答、建立或续接任务、查询状态及发布结果 |
| Coordinator | 并发、任务版本、取消、恢复、时限与结果提交 |
| Store | SQLite 原始消息、任务、输入、执行记录、结果和 Outbox |
| Worker | 在所属任务的工作空间内使用已启用能力完成交付 |
| 定时任务服务 | 计划、权限、到期扫描、执行及投递状态 |
| 管理后台 | 业务和模型配置、任务管理、审计及用量查看 |

模型推理、工具循环、会话存储和压缩由 dsh 提供。宿主约束动作作用域、来源、任务归属、版本和投递；领域事实及专用校验由外部能力负责。

## 群聊与任务

当前消息需要明确 @ 机器人或直接呼唤配置称呼，才能发起新的回应。历史 @、引用或追问不会自动继承唤起。已接纳任务的结果可继续投递。

Thread 表示一个持续话题，保存请求人、参与者、输入和任务状态。明确引用按已解析的任务绑定续接；没有引用时，Router 根据对象、范围和讨论关系判断续接或新建，必要时检索同群历史。不同作者可以讨论同一公共资料，个人条件仍需分别归属；相同关键词或链接不构成强制合并条件。

追加条件会更新任务修订号。运行中的 Worker 可以接收补充；结果未覆盖最新输入时不能发布，而是以新条件续跑。同一 Thread 同时只有一个活动 Worker，独立交付目标可以建立独立 Thread。Thread 不提供多个独立请求分别排队交付的保证。

## 状态与交付

原始消息、任务条件、已验证检查点和发送回执分别来自持久状态。模型摘要用于上下文压缩，不授予写入、工具调用或任务管理权限。

结果提交核对 Thread、run、revision 和 epoch。取消、条件变更或失效的定时执行会阻止旧结果继续发布。Worker 执行结束、任务目标完成和平台确认投递是不同状态，后台分别展示。

Outbox 在发送前持久化输出，按回执区分成功、明确失败、未尝试和不确定状态。不确定投递保留审计，避免盲目重发；平台协议不提供严格的端到端 exactly-once 保证。文件上传和消息回执的细节见 [平台接入](platform.md)。

## 能力与隔离

业务配置选择提示词、人格、skill、扩展和成员字段；默认配置不装载领域能力。skill 提供知识和可移植脚本，扩展提供工具及业务校验，Cordis 插件扩展 Agent 运行时。

运行数据由 `stateDir` 指定，外部 skill 和模块各自配置路径。通用文件工具只写任务空间，共享技能目录只读。扩展、插件和 MCP 属于部署者信任的本地代码，应使用适当的系统权限隔离。参见 [能力接入](skills.md) 与 [安全说明](../SECURITY.md)。

配置和使用见 [配置参考](configuration.md)，运行装配见 [原生运行时](runtime.md)，持续 Router 的上下文和恢复见 [Router 上下文](router-context.md)。
